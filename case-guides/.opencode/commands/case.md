---
description: 事例（設計ガイド / 導入アーキテクチャ）を work/<フォルダ名> の素材から作成・再開する（例: /case vector）
---

`case-guides/AGENTS.md` に従って、事例コンテンツを作成します。対象の作業フォルダ名: `$ARGUMENTS`

作業を始める前に、次の確認を順に行ってください。どれかで止まった場合は、理由と SE がすべきことを伝えて終了します。

1. **フォルダ名の確認**
   - フォルダ名が空の場合: `work/` 配下のフォルダ一覧（`.gitkeep` を除く）を示し、どのフォルダで作業するかを SE に質問する。
   - フォルダ名が英小文字・数字・ハイフン以外を含む場合: AGENTS.md の命名規則を示して止まる。
   - フォルダ名が顧客名・社名を含んでいる可能性がある場合: 顧客名を含めない規則を伝え、このまま進めてよいかを SE に確認する。
2. **フォルダと素材の確認**（`work/<フォルダ名>/`）
   - フォルダがない場合: `work/<フォルダ名>/raw/` と `work/<フォルダ名>/context/` を作成し、
     `raw/` にスクリーンショット、`context/` に補足資料を置いてから再度 `/case <フォルダ名>` を実行するよう伝えて止まる。
   - `raw/` に画像（png / jpg / jpeg / webp）が 1 枚もない場合: スクリーンショットを置くよう伝えて止まる。
   - `raw/` の画像の枚数と、`context/` のファイル一覧を報告する。
3. **新規か再開かの判定**
   - `index.html` がない場合: 新規として、AGENTS.md「3. 作業手順」の 0（種別の確認）から始める。
     種別は必ず question ツールで「これは設計ガイドですか、導入アーキテクチャ説明ですか」と質問し、推測で決めない。
   - `index.html` がある場合: `notes.md` のコンテンツ種別、`masks.json` の記載と `reviewed` の状況、
     `index.html` に残っている `{{...}}` の数、`work/<フォルダ名>.zip` の有無から、どの手順まで済んでいるかを判断して報告し、
     「続きから再開する」か「最初からやり直す」かを SE に質問する。やり直す場合も `raw/` と `context/` は消さない。
   - 導入アーキテクチャで `context/` が空の場合は、AGENTS.md 3 の 2 に従って資料の追加を依頼して止まる。

確認が済んだら、AGENTS.md「3. 作業手順」を順に実行します。各手順の完了時に 1〜2 行で報告し、
SE への提示・確認が必要な手順（棚卸し、マスク一覧、目次案、接続図の構成、最後の報告）では、SE の回答を待ってから次に進んでください。
